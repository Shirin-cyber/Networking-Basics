## 2.1.1 Video: Clients and servers

Ok, so the first big idea is that a computer on a network isn't *born* a client or a server. A computer host can act as a **client**, a **server**, or **both**, and what decides that is the **software installed on it**. Same kind of machine, different job, depending on what's running on it.

- **Servers** = hosts with software that lets them **provide** information to other hosts on the network, like email or webpages.
- **Clients** = hosts with software that lets them **request and display** the information they get from a server.

And each service needs its own server software. So a web service and an email service are not the same program.

### Quick examples

**Web:** my browser (Chrome, Edge, Safari, Firefox) is the client software. I ask a web server for a webpage, and the server sends the page back.

**Email:** an email app like Microsoft Outlook is the client software. It connects to the email server so I can both send and receive messages.

I never really thought about it, but every time I open a browser I'm literally being a client.

## 2.1.2 Client and server roles

A couple of definitions to lock in:

- **Host** = any computer connected to the network that participates directly in network communication. Hosts can send and receive messages. (That's the same "host" word from Module 1 and the Module 2 intro.)
- Whether a host is a client, a server, or both depends on its software.

This part connects back to something from Module 1: **every destination I visit online is provided by a server** located somewhere on a network that's connected to the global internet. In 1.1 it said everything I access online lives somewhere on the internet. Now I know what's *doing* the serving.

### The 3 examples they gave

| Type | How it works |
|---|---|
| **Email** | The email server runs **email server software**. Clients use **mail client software**, like Microsoft Outlook, to get to the email on the server. |
| **Web** | The web server runs **web server software**. Clients use **browser software** to access web pages on the server. |
| **File** | The file server stores company and user files in **one central place**. Client devices use client software, like Windows File Explorer, to access those files. |

## 2.1.3 Peer-to-peer (P2P) networks

Client software and server software *usually* run on separate computers. But one computer can run **both at the same time**. In homes and small businesses, a lot of computers do exactly that, being servers and clients at once. That setup is called a **peer-to-peer (P2P) network**.

- **Simplest P2P network:** two computers connected directly, wired or wireless. They can swap data and services, with each acting as a client or a server whenever needed.
- **Bigger P2P network:** you can connect more PCs, but then you need a network device like a **switch** to connect them all together. (Switch is a new word. I'll be seeing more of those soon, I think.)

### Pros and cons

| Advantages | Disadvantages |
|---|---|
| Easy to set up | No centralized administration |
| Less complex | Not as secure |
| Lower cost, since you might not need extra network devices or dedicated servers | Not scalable (doesn't grow well) |
| Good for simple stuff like transferring files and sharing printers | Devices acting as both client and server can slow down |

The big downside is that last one: if a computer is acting as a client and a server at the same time, its performance can drop.

That also explains why **larger businesses use dedicated servers**. With lots of traffic and tons of service requests, they can't have regular computers doing double duty. They need machines that just serve.

## 2.1.4 Peer-to-peer applications

Careful, because this one sounds like the last topic but it's a slightly different thing. Before, **P2P network** was about how a network is set up. Now, a **P2P application** is about what happens inside the *same* communication:

- A device acts as **both a client and a server** in the same communication.
- Every client is a server, and every server is a client.
- Each end device needs to provide a **user interface** and run a **background service**.

### The hybrid version

Some P2P applications are **hybrid**:

- Resource sharing is **decentralized** (the stuff lives on the peers).
- But the **indexes** that point to where things are stored are kept in a **centralized directory**.
- So a peer first asks an **index server** where a resource is, then goes to the other peer that has it.

It's like asking a librarian which shelf has a book, then walking over and getting it yourself. I'm guessing this is how file-sharing apps work, but the course doesn't say.

## 2.1.5 Multiple roles in the network

Here's where it all comes together:

- A computer with server software can serve **one client or many clients at the same time**.
- One computer can run **several types of server software**. In a home or small business, one computer might be a **file server, a web server, and an email server** all at once.
- One computer can also run **several types of client software**. You need client software for every service you want to use.
- With multiple clients installed, a host can connect to **multiple servers at the same time**.

So right now on my own device, I can be checking email, viewing a web page, messaging someone, and listening to internet radio. That's four client services running in parallel, each talking to a different server.

## What I want to remember

- A host can be a **client**, a **server**, or **both**. The **software** decides which.
- **Servers** provide information (email, web pages, files). **Clients** request and display it.
- Each service needs its own **server software** and its own **client software**.
- **P2P networks**: small, simple, cheap, and easy to set up, but not very secure or scalable, and they can slow down.
- **P2P applications**: every client is also a server. **Hybrid** ones use a central index to find resources on other peers.
- One computer can run many server programs and many client programs at once.
