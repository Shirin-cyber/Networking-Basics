## The big picture

This module is about the **rules** that make communication work. It builds up in three steps:

1. **What are protocols?** (5.1 Communication Protocols)
2. **How does everyone agree on them?** (5.2 Communication Standards)
3. **How do I organize all of them in my head?** (5.3 Network Communication Models)

So it goes rules, then agreement, then a way to picture them all.

---

## 5.1 Communication Protocols

- **Protocols** are the rules for communication. Before people communicate, they agree on the **method**, the **language**, and whether to **confirm** a message was received.
- Human protocols have network versions:

| Human protocol | Network version |
|---|---|
| Identified sender and receiver | **Encapsulation** (addressing in the header) |
| Agreed method of communicating | The **channel/media**, which affects the **message format** |
| Common language and grammar | **Message format** and **encoding** |
| Speed and timing | **Timing** and **message size** |
| Confirmation or acknowledgment | **Message pattern** (request/response) |

- A **local network** works when all hosts **share a common protocol**. Without that, they can't communicate.
- Protocols define six things: **message format**, **message size** (big messages get split up), **timing**, **encoding** (bits turned into sounds, light, or electrical impulses), **encapsulation** (adding a header with source and destination addresses), and **message pattern** (some messages need an acknowledgment, others are just streamed).

## 5.2 Communication Standards

- A device doesn't see the network like a topology diagram does. Each device is in its **own bubble** and only knows its own addressing info.
- **Protocols** answer the questions a device has: what's my IP address, is the destination local or remote, where do I send this next, and do I need to resend?
- Messages are broken into **packets**.

| Protocol | Its job |
|---|---|
| **Ethernet / wireless** | Physically connect the device to the network |
| **DHCP / ICMPv6** | Provide IP addressing info (IP address, default gateway, DNS server) |
| **DNS** | Finds the IP address that goes with a domain name |
| **IP** | Delivers the packet from source to destination, like a letter |
| **TCP** | Guarantees reliability and **resends** lost packets |

- A **standard** is a set of rules that determines how something must be done, so **different devices** can communicate (like an email sent from a PC and read on a phone).
- Standards come out of **discussion, problem solving, and testing**, and are tracked in numbered **RFCs**, published and managed by the **IETF**.

| Organization | What it does |
|---|---|
| **IETF** | Publishes and manages RFCs for internet standards |
| **IEEE** | Creates wireless technical standards like 802.11 |
| **Wi-Fi Alliance** | Tests wireless devices from different manufacturers |
| **ISO** | Created the OSI reference model |

## 5.3 Network Communication Models

- A message uses **several protocols at once**, called a **protocol stack**. For a web page: **HTTP** (application), **TCP** (transport), **IP** (internet), and **Ethernet** (network access).
- **Layered models** help with protocol design, let different vendors' products work together, let one layer change without affecting the others, and give a common language.
- There are two kinds of models: a **protocol model** (matches a specific protocol suite) and a **reference model** (describes functions, not how to do them).

| TCP/IP model (protocol model) | OSI model (reference model) |
|---|---|
| **Application** | **7. Application**, **6. Presentation**, **5. Session** |
| **Transport** | **4. Transport** |
| **Internet** | **3. Network** |
| **Network Access** | **2. Data Link**, **1. Physical** |

- **TCP/IP** is what the internet actually uses. **OSI** is used for design, specifications, and troubleshooting, and it's the one people use for the **lower layers** (data link and physical).
- A few OSI layer jobs: **Physical** = bits as signals on the media, **Data Link** = exchanging **frames**, **Network** = moving data between identified end devices, **Transport** = segmenting and reassembling data.

## How it all connects

Here's what happens when I open a web page, with all three topics in one story:

1. My device is connected by **Ethernet or wireless**, and it got its addressing info from **DHCP**.
2. I ask for the page, and the device asks a **DNS server** for the **IP address** of the domain name.
3. The message is made of **several protocols** from the **protocol stack**: **HTTP** (what I'm asking for), **TCP** (make sure it all arrives, in order), **IP** (get it to the right destination), and **Ethernet** (get it across the local network).
4. The message is **encapsulated** with headers and broken into **packets**.
5. Everything works because every device follows the **same standards**, which come from organizations like the **IETF** and **IEEE**.
6. If something breaks, I can use the **layers** to narrow down where the problem is.

## Key terms cheat sheet

| Term | What it means |
|---|---|
| **Protocol** | A rule for how devices communicate |
| **Standard** | A set of rules that determines how something must be done |
| **Encoding** | Turning bits into signals (sound, light, or electrical impulses) |
| **Encapsulation** | Adding a header with addressing info to data |
| **Packet** | A smaller piece of a message sent across the network |
| **Frame** | The data unit exchanged at the data link layer |
| **Protocol stack** | The set of protocols used together to send a message |
| **Layered model** | A way of showing how protocols work at different layers |
| **TCP/IP model** | The 4-layer protocol model used for the internet |
| **OSI model** | The 7-layer reference model |
| **IP** | Delivers packets from source to destination |
| **TCP** | Reliable delivery, resends lost packets, and reorders packets |
| **HTTP** | Governs the transfer of HTML for web pages |
| **Ethernet** | Governs NIC-to-NIC communication in the same network |
| **DHCP / ICMPv6** | Provide IP addressing info |
| **DNS** | Finds the IP address for a domain name |
| **RFC** | A numbered document tracking how a standard developed |
| **IETF** | Publishes and manages RFCs for internet standards |

## Back to Kishori

Kishori and Srinivas had two very different native languages, so they agreed to use **English**. And Kishori might have him **sign a document** to show he understood.

That's the whole module in one story. English is the **standard** that lets them communicate, the agreed rules are the **protocols**, and the signature is the **acknowledgment**, which is what **TCP** does for packets. Devices have to do exactly the same thing, just faster and with way more rules.
