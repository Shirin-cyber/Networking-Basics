## 5.3.1 Video: Network protocols

The video starts by repeating the idea from this whole module: computer networks use **protocols**, the rules that govern communication, and it's **very similar to how humans communicate**.

With people, a protocol could be:

- a common **language**
- talking **formally or informally**
- how we **greet** each other
- even how we **dress or act**

Computers use protocols to govern communication between two devices, too. And a single computer message is actually made up of **several protocols at once**:

| Protocol | What it governs |
|---|---|
| **Ethernet** | Communication from **network interface card (NIC) to NIC** within the **same network** |
| **IP (Internet Protocol)** | Communication from the **original source all the way to the final destination**. The **routers** along the way know where the packet is going because of IP. |
| **TCP (Transmission Control Protocol)** | Makes sure the information gets there **reliably**. If packets from the same message arrive **out of order**, TCP **re-orders** them properly. |
| **HTTP (Hypertext Transfer Protocol)** | Governs the **exchange or transfer of HTML** (Hypertext Markup Language) |

So when I request or download a web page, the message contains **all four** of these protocols.

**Why learn this?** Understanding protocols helps me understand **how networks operate**, how to **implement and configure** them, and how to **troubleshoot** them. That last one connects to the course goal about using tools to test and troubleshoot connectivity.

**Connecting the dots:** this is the stuff from 5.2.1 (Ethernet, IP, TCP) with another one added (HTTP), and now I get to see them as a team. The "re-ordering" bit is new too. Packets from the same message can arrive out of order, and TCP fixes that.

## 5.3.2 Video: The protocol stack

Successful communication needs **several protocols working together**. That group of protocols is called a **protocol stack**. The video shows it using the **TCP/IP model**, which has **four layers**:

1. **Network Access**
2. **Internet**
3. **Transport**
4. **Application**

When a device creates a message, it uses protocols from **different layers**. Here's the web page example:

| Layer | Protocol used | What it does |
|---|---|---|
| **Application** | **HTTP** | Governs the exchange/transfer of HTML |
| **Transport** | **TCP** | Makes sure the message gets there **reliably** |
| **Internet** | **IP** (version 4 or version 6) | Gets the message from the **original source to the final destination**, whether that's **in the same network** or across **multiple networks** |
| **Network Access** | **Ethernet** | NIC-to-NIC communication in the **same network** |

So sending one message takes **multiple protocols from the stack.**

**Connecting the dots:**

- Now the protocols from 5.2.1 have a home. Ethernet and wireless are at the **network access** layer, IP is at the **internet** layer, and TCP is at the **transport** layer.
- I'm guessing DNS and DHCP (also from 5.2.1) fit in the **application** layer, but the course hasn't said yet.
- IP can be version 4 or 6, which lines up with the IPv4 and IPv6 goals from the course intro.

## 5.3.3 The TCP/IP model

A **layered model** helps me picture how different protocols work together. It shows what the protocols in **each layer** do and how each layer interacts with the ones **above and below**.

### Why layered models are useful

| Benefit | What it means |
|---|---|
| **Helps with protocol design** | Protocols at a layer have **defined info they act on** and a **defined interface** to the layers above and below |
| **Encourages competition** | Products from **different vendors can work together** |
| **Lets technology change at one level** | A change at one layer **doesn't affect the others** |
| **Gives a common language** | A shared way to **describe networking functions and capabilities** |

**Connecting the dots:** the "different vendors can work together" part is the standards idea from 5.2.2 again. And the "change one level without affecting the others" part makes sense to me when I think about switching from Wi-Fi to a cable. I'd be changing the bottom layer, but I'd still browse the web the same way.

### The TCP/IP model (a.k.a. the internet model)

- The **first layered model** for internetwork communication was created in the **early 1970s** and is called the **internet model**.
- It defines **four categories of functions** that have to happen for communication to work.
- The **TCP/IP protocol suite** follows this structure, which is why it's commonly called the **TCP/IP model**.

| TCP/IP layer | What it does |
|---|---|
| **Application** | Represents data to the user, plus **encoding and dialog control** |
| **Transport** | Supports communication between different devices across **diverse networks** |
| **Internet** | Determines the **best path** through the network |
| **Network Access** | Controls the **hardware devices and media** that make up the network |

## 5.3.4 The OSI reference model

There are two basic types of models for describing the functions needed for network communication:

| | Protocol model | Reference model |
|---|---|---|
| **What it does** | **Matches the structure of a particular protocol suite** (a set of related protocols that provides all the functionality needed for a data network) | Describes the **functions** that must happen at each layer, but **not exactly how** to do them |
| **Level of detail** | Detailed enough to describe each layer of that suite | **Not** detailed enough to define how each protocol should work |
| **Purpose** | | To help me **understand the functions and processes** needed for network communication |
| **Example** | **TCP/IP model** | **OSI model** |

The **OSI model** is the most widely known internetwork reference model. It was created by the **Open Systems Interconnection (OSI)** project at the **International Organization for Standardization (ISO)**. It's used for **network design, operation specifications, and troubleshooting**.

**Connecting the dots:** ISO is another standards organization to add to my list from 5.2.3, next to the IETF, IEEE, and the Wi-Fi Alliance.

### The 7 OSI layers

| # | Layer | What it does |
|---|---|---|
| **7** | **Application** | Protocols used for **process-to-process communications** |
| **6** | **Presentation** | Provides a **common representation of the data** transferred between application layer services |
| **5** | **Session** | Provides services to the presentation layer to **organize its dialogue** and **manage data exchange** |
| **4** | **Transport** | Services to **segment, transfer, and reassemble** the data for individual communications between end devices |
| **3** | **Network** | Services to **exchange the individual pieces of data** over the network between **identified end devices** |
| **2** | **Data Link** | Methods for exchanging **data frames** between devices over a **common media** |
| **1** | **Physical** | The **mechanical, electrical, functional, and procedural** means to activate, maintain, and de-activate physical connections for **bit transmission** to and from a network device |

A memory trick (not from the course, just one I know): *"**P**lease **D**o **N**ot **T**hrow **S**ausage **P**izza **A**way"* goes from layer 1 up to layer 7.

**Connecting the dots:**

- **Frames:** in 4.3.2, the SSID is sent in the header of every **frame**, and I didn't know what a frame was. Now I do. **Layer 2 (Data Link)** exchanges **data frames** between devices on a common media.
- **Layer 1** is all the stuff from 1.2: **bits** turned into **electrical, light, or radio signals** on the media.
- **Layer 4** (segment, transfer, reassemble) matches what TCP does: **breaking messages into pieces and putting them back in order**.
- **Layer 3** exchanging data between **identified end devices** goes with the **addresses** from 2.2.3 and the IP stuff from 5.2.1.

## 5.3.5 OSI model and TCP/IP model comparison

**The big question:** TCP/IP is what the internet actually uses, so why learn OSI too?

- The TCP/IP model only describes the functions **for the protocols in the TCP/IP suite**. It doesn't describe the general functions that **all** network communication needs.
- Example: at the **network access** layer, TCP/IP doesn't say **which protocols to use** over a physical medium or **how to encode the signals**. **OSI layers 1 and 2** cover the procedures for accessing the media and the physical means of sending data.
- But TCP/IP protocols **can be described using OSI**.

### How the layers line up

| TCP/IP model | OSI model |
|---|---|
| **Application** | **7. Application**, **6. Presentation**, **5. Session** |
| **Transport** | **4. Transport** |
| **Internet** | **3. Network** |
| **Network Access** | **2. Data Link**, **1. Physical** |

- **Transport** works the same in both models.
- **Internet** (TCP/IP) = **Network** (OSI).
- **Network Access** and **Application** in TCP/IP are **split into more layers** in OSI to describe separate functions.

### The key similarities and differences

- **OSI Layer 3 (Network)** maps directly to the **TCP/IP Internet layer**. It's used for protocols that **address and route** messages through an internetwork.
- **OSI Layer 4 (Transport)** maps directly to the **TCP/IP Transport layer**. It describes the general services that give **ordered and reliable delivery** between source and destination hosts.
- The **TCP/IP Application layer** includes protocols that provide specific functionality to many end-user applications. **OSI layers 5, 6, and 7** are used as references for **software developers and vendors** building network applications.
- **Both models** are commonly used to refer to protocols at different layers. Since OSI **separates the data link layer from the physical layer**, it's commonly used when talking about those **lower layers**.

### The protocols from the video, in both models

| Protocol | TCP/IP layer | OSI layer(s) |
|---|---|---|
| **HTTP** | Application | 5, 6, 7 |
| **TCP** | Transport | 4 |
| **IP** | Internet | 3 |
| **Ethernet** | Network Access | 1 and 2 |

**Connecting the dots:** this is the answer to my guess in the Module 5 README. I thought OSI and TCP/IP were frameworks that break communication into pieces, and they are. TCP/IP is the **one the internet actually uses** (a protocol model), and OSI is the **general one for talking about functions** (a reference model). I'll probably use OSI layer numbers a lot when troubleshooting, since people use them to say things like "that's a layer 2 problem."

## What I want to remember

- A message uses **several protocols at once**, called a **protocol stack**: **Ethernet** (network access), **IP** (internet), **TCP** (transport), **HTTP** (application).
- **TCP** also puts packets back in order when they arrive out of order.
- **Layered models** help protocol design, let different vendors' products work together, let one layer change without affecting the others, and give us a common language.
- **TCP/IP model** (protocol model, 4 layers): Application, Transport, Internet, Network Access.
- **OSI model** (reference model, 7 layers): Application, Presentation, Session, Transport, Network, Data Link, Physical.
- **Mapping:** OSI 5-7 = TCP/IP Application, OSI 4 = Transport, OSI 3 = Internet (Network), OSI 1-2 = Network Access.
- **TCP/IP** is what the internet uses. **OSI** is used for **design, specifications, and troubleshooting**, and it's the one people use for the lower layers.
