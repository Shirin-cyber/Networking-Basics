## 7.2.1 Video: Ethernet switches

Ethernet switches work at **layer 2, the data link layer** of the OSI model. The reason is that a switch makes its **forwarding decisions** based on **layer 2 info**, which is the **Ethernet header** information in the frame.

**Connecting the dots:** this is the data link layer from 5.3.4, where **frames** get exchanged. And the header the switch reads is the **source and destination MAC addresses** from 7.1.1. So the switch is basically reading the **outside of the envelope**.

### The MAC address table

A switch has a **MAC address table**. (In this video it's already filled in. The next video shows how it gets built.)

The example has **four hosts, H1 to H4**, each with an abbreviated MAC address:

| Host | MAC (abbreviated) | Switch port |
|---|---|---|
| H1 | **AAAA** | **Fa0/1** (FastEthernet 0/1) |
| H4 | **DDDD** | **Fa0/4** (FastEthernet 0/4) |

(H2 and H3 are on the other ports.)

### What happens when H1 sends a frame to H4

1. H1 builds an Ethernet frame. The **source MAC** is **AAAA** (its own NIC), and the **destination MAC** is **DDDD** (H4's NIC).
2. The frame is sent to the switch and arrives on **Fa0/1**.
3. The switch looks at the **destination MAC address**, **DDDD**, and finds it in its table on **Fa0/4**.
4. The switch forwards the frame **only out Fa0/4**, toward H4.

**Connecting the dots:**

- The switch only sends the frame where it needs to go, instead of to everyone. I think this is part of how switches **improve communication at the access layer**, but the course doesn't say that outright here.
- This is what the **internal switch** in a home router (4.1.3) does with its **LAN ports**. It's also the "network device such as a switch" in 2.1.3 that a bigger P2P network needs.

## 7.2.2 Video: MAC address tables

Now the question from before: **how does a switch build its MAC address table?** It's still making forwarding decisions based on layer 2 info, the **Ethernet header**.

### The 2 things a switch does with every frame

1. **Learn:** look at the **source MAC address**. Have I learned anything new?
2. **Forward:** look at the **destination MAC address**. Do I know where to send this?

### Walkthrough (starting with an empty table)

**Frame 1: H1 sends to H4** (source **AAAA**, destination **DDDD**)

- **Learn:** the frame arrives on **Fa0/1** with source **AAAA**. That's not in the table yet, so the switch **adds AAAA to Fa0/1**.
- **Forward:** the destination **DDDD** isn't in the table either. This is called an **unknown unicast**. The switch doesn't know where to send it, so it acts like the **old Ethernet hubs** and sends the frame out **every port except the one it came in on**.
- Every host gets the frame. Each NIC **compares its own MAC address** to the destination MAC in the frame:
  - **H2:** no match, so it **ignores the rest of the frame**.
  - **H3:** no match, so it **ignores** it too.
  - **H4:** it's a match, so it **receives the whole frame**.

**Frame 2: H4 replies to H1** (source **DDDD**, destination **AAAA**)

- **Learn:** the frame arrives on **Fa0/4** with source **DDDD**. That's new, so the switch **adds DDDD to Fa0/4**.
- **Forward:** the destination **AAAA** is in the table, on **Fa0/1**. So the switch **filters** the frame and sends it **out that single port**.

**Frame 3: H1 sends to H4 again** (source **AAAA**, destination **DDDD**)

- **Learn:** the switch already knows **AAAA** on **Fa0/1**. Switches keep this info for **about 5 minutes**.
- **Forward:** this time it **knows DDDD** is on **Fa0/4**, so it sends the frame **only out Fa0/4**. It doesn't send it out of all the ports like it did at first.

### How the table grew

| After... | MAC address table |
|---|---|
| Start | *(empty)* |
| Frame 1 (H1 to H4) | AAAA = Fa0/1 |
| Frame 2 (H4 to H1) | AAAA = Fa0/1, DDDD = Fa0/4 |
| Frame 3 (H1 to H4) | No change. Both are already known. |

| Frame | Learns | Forwards |
|---|---|---|
| **1** (H1 to H4) | AAAA on Fa0/1 | DDDD unknown, so **out every port except Fa0/1** |
| **2** (H4 to H1) | DDDD on Fa0/4 | AAAA known, so **only out Fa0/1** |
| **3** (H1 to H4) | Already known | DDDD known, so **only out Fa0/4** |

**Connecting the dots:**

- **The switch learns by listening.** Nobody has to program the table. It builds itself from the **source MAC addresses** of the frames passing through. That's pretty clever.
- The "unknown unicast" case is the only time the switch acts like a hub. After it learns, it gets more efficient.
- **Why do NICs compare MAC addresses?** Because each NIC has a unique MAC address (7.1.1). That's how H2 and H3 know the frame isn't for them, even though they received it.
- The video says "5 minutes" for how long the info is kept. The course doesn't give a name for that, so I'm just noting it.
- The video doesn't use the word "flooding," but I think that's the term for sending a frame out every port except the incoming one.

## What I want to remember

- **Ethernet switches work at layer 2 (data link).** They make decisions using the **MAC addresses** in the Ethernet frame header.
- A switch has a **MAC address table**: which MAC address is on which port.
- For every frame, a switch does two things: **learn** from the **source MAC**, then **forward** based on the **destination MAC**.
- If the destination is **known**, the switch sends the frame **only out that port**. If it's an **unknown unicast**, it sends it **out every port except the incoming one**.
- Each NIC checks the **destination MAC**. If it doesn't match, the NIC **ignores** the frame. If it matches, it **receives** the whole thing.
- Learned entries are kept for about **5 minutes**.
