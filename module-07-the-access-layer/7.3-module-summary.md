## The big picture

This module zooms in on how messages actually move across an **Ethernet** network. It goes in two steps:

1. **What does a message look like on the wire?** (7.1 Encapsulation and the Ethernet Frame)
2. **How does it get to the right device?** (7.2 The Access Layer)

So first the envelope, then the post office that sorts it.

---

## 7.1 Encapsulation and the Ethernet Frame

- **Ethernet** is the technology commonly used in LANs. Devices connect with an **Ethernet NIC**, and each NIC has a unique, permanent **MAC address**.
- **Encapsulation** = putting one message format inside another (a letter in an envelope). **De-encapsulation** = taking it back out.
- A **frame** acts like an envelope. It carries the **destination** and **source** addresses, and messages that aren't formatted correctly aren't delivered.

### The Ethernet frame

| Field | What it does |
|---|---|
| **Preamble** | Gets the receiving NIC in sync with the incoming bits |
| **Start frame delimiter** | Marks where the actual frame information begins |
| **Destination MAC** | The MAC address of the NIC the frame is going to |
| **Source MAC** | The MAC address of the NIC that sent the frame |
| **Length / type** | The length of the data, or the type of data (like IPv4 or IPv6) |
| **Data** | The encapsulated data (like an IP packet with TCP and HTTP headers) |
| **FCS** | Frame Check Sequence, used by the receiver for error checking |

- Ethernet **doesn't care what's in the data**. It just delivers it NIC to NIC.
- There are **two envelopes**: the **Ethernet frame** gets the message across the **local network** (MAC addresses), and the **IP packet** gets it from **source to final destination** across one or more networks (IP addresses).

## 7.2 The Access Layer

- **Ethernet switches** work at **layer 2 (data link)**. They make forwarding decisions based on the **MAC addresses** in the frame header.
- A switch has a **MAC address table** that tracks which MAC address is on which port.
- For every frame, the switch does two things:

| Step | What it looks at | What it does |
|---|---|---|
| **Learn** | The **source MAC** | Adds it to the table, with the port it arrived on |
| **Forward** | The **destination MAC** | If known, sends it **only out that port**. If it's an **unknown unicast**, sends it out **every port except the incoming one**. |

- A host's NIC compares its own MAC to the destination MAC. If it **doesn't match**, the NIC **ignores** the frame. If it **matches**, it receives the whole frame.
- A switch keeps what it learns for about **5 minutes**.

## How it all connects

Here's one message going from Kishori's desktop to a server, using everything from this module:

1. The desktop builds a message. The **IP packet** gets put inside an **Ethernet frame**, with the desktop's **MAC** as the source and the next device's **MAC** as the destination.
2. The frame travels down the **twisted-pair cable** to a **switch** on the **Ethernet** network.
3. The switch **learns** the desktop's MAC and port from the **source MAC**.
4. The switch **forwards** the frame based on the **destination MAC**. If it's known, the frame goes out one port. If not, it goes out every port except the incoming one.
5. The right NIC sees a **matching MAC** and receives the frame. Every other NIC **ignores** it.
6. The receiving device does **de-encapsulation**, takes the packet out of the frame, and uses it.

## Key terms cheat sheet

| Term | What it means |
|---|---|
| **Ethernet** | The technology commonly used in LANs |
| **NIC** | The network interface card that connects a device to the network |
| **MAC address** | A unique address permanently embedded on each NIC |
| **Encapsulation** | Placing one message format inside another |
| **De-encapsulation** | Taking the message back out of the format it was placed in |
| **Frame** | The "envelope" for a message on a network, with source and destination addresses |
| **Preamble / start frame delimiter** | Fields that sync the receiving NIC and mark the start of the frame |
| **Payload** | The data portion of a frame |
| **FCS** | Frame Check Sequence, used for error checking |
| **Layer 2** | The data link layer of the OSI model, where switches work |
| **MAC address table** | A switch's list of MAC addresses and the ports they're on |
| **Unknown unicast** | A frame whose destination MAC isn't in the switch's table |
