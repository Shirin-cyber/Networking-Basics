## 7.1.1 Video: The fields of the Ethernet frame

**Ethernet** is the technology commonly used in **local area networks**. A device gets onto an Ethernet LAN using an **Ethernet NIC** (network interface card).

Every Ethernet NIC has a **unique address permanently embedded on the card**. It's called a **Media Access Control (MAC) address**. And the **source and destination MAC addresses** are both fields in an **Ethernet frame**.

**Connecting the dots:** MAC address and NIC were both on my "terms I'll be seeing later" list from 5.2.1, and here they are. The MAC address is built into the card, which is different from an IP address, since I learned the IP address comes from something like DHCP.

Also, the video reminds me: **Ethernet is for NIC to NIC on the same network.** That's the same thing 5.3.1 said.

### The fields of the frame

The video says the numbers under each field in the course figure are the **number of bytes**. To get **bits**, multiply by 8. (From 1.2, 8 bits = 1 byte.)

| Field | What it does |
|---|---|
| **Preamble** | Gets the **receiving NIC in sync** with the bits coming down the cable |
| **Start frame delimiter** | Tells the receiving NIC that what comes **after this** is the **actual information** of the frame |
| **Destination MAC address** | The MAC address of the **NIC the frame is going to** on this network |
| **Source MAC address** | The MAC address of the **NIC that sent** the frame |
| **Length / type** | Can be **one of two things**: the **length** of the data (how many bytes in the data portion, also called the **payload**), or a **type** that says **what kind of data** it is, like an **IPv4 packet** or an **IPv6 packet** |
| **Data** | The **encapsulated data**: could be an **IPv4 or IPv6 packet**, with the **TCP header**, the **HTTP header**, or whatever else was encapsulated |
| **FCS (Frame Check Sequence)** | Used by the **receiving device** to do **error checking**, to make sure there were **no errors** during transmission |

One thing I liked: **Ethernet doesn't care what kind of data is inside.** It just delivers the data from NIC to NIC.

**Connecting the dots:**

- The **data** field is the protocol stack from 5.3.2, nested. The frame holds an **IP packet**, which holds a **TCP** header, which holds **HTTP**. So the layers are like envelopes inside envelopes.
- The **type** field is how the receiver knows whether the data inside is **IPv4 or IPv6**, which are both on the course goals list.
- **FCS** checks for errors in transmission. That's a different job from **TCP**, which makes sure data arrives and resends it if it doesn't. The course doesn't compare them here, so that's just how I'm thinking about it.
- The byte sizes are in the course figure but not in the transcript, so I'm leaving them out. I can fill them in from the figure.

## 7.1.2 Encapsulation

When I write a letter, I use an **accepted format** so it gets delivered and understood. A message sent over a computer network works the same way. It follows **specific format rules** so it can be delivered and processed.

- **Encapsulation** = placing one message format (the **letter**) inside another (the **envelope**).
- **De-encapsulation** = the **reverse**. The recipient takes the letter out of the envelope.

On a network:

- Every computer message is **encapsulated in a specific format called a frame** before it's sent.
- A frame acts like an **envelope**. It gives the **address of the destination** and the **address of the source host**.
- The **format and contents** of a frame depend on the **type of message** and the **channel** it's sent over.
- A message that **isn't formatted correctly** won't be **delivered to or processed by** the destination host.

**Connecting the dots:** this is the **message format** from 5.1.2, now with the name **frame**. Also, "the format depends on the channel" might be what Rina meant in the Module 7 intro. The same message can go over a cable or over Wi-Fi, but it's packaged differently depending on the channel. The course doesn't spell out the wireless version here, so that's a guess.

### The letter analogy

The course animation shows a letter being mailed:

- **Envelope (outside):** the **recipient's address** (1400 Main Street, Canton, Ohio) and the **sender's address** (4085 SE Pine Street, Ocala, Florida), plus a **stamp**.
- **Letter (inside):** "Dear **Jane**, I just returned from my trip. I thought you might like to see my pictures. **John**."

If the address or formatting is wrong, the letter **isn't delivered**.

The course breaks the letter down like this:

| Part of the letter | What it's called |

| Sender's location address (on the envelope) | **Sender (source) location address** |
| "Dear" | **Salutation** (start of message indicator) |
| "Jane" | **Recipient (destination) identifier** |
| "I just returned from my trip..." | **Content of letter** (the encapsulated data) |
| "John" | **Sender (source) identifier** |
| The stamp | **End of frame** (end of message indicator) |

## IP is an envelope too

The network version: **Internet Protocol (IP)** does a job **similar to the envelope**. In the course figure, the fields of an **IPv6 packet** identify the **source** and **destination** of the packet. And IP is responsible for sending a message from the **source to the destination** over **one or more networks**.

(The fields of the IPv6 packet are covered in detail in another module.)

**Connecting the dots:** so there are really **two envelopes**:

| Envelope | Gets the message... | Addresses used |
|---|---|---|
| **Ethernet frame** | from **NIC to NIC** on the **same network** | **MAC** addresses |
| **IP packet** | from the **source to the final destination** across **one or more networks** | **IP** addresses |

That clears up what 5.3.1 was saying. Ethernet handles the hop across the local network, and IP handles the whole trip. And it fits with 5.2.1, where the IP packet is delivered "like a letter" from source to destination.

## What I want to remember

- **Ethernet** is used in LANs. Devices connect with an **Ethernet NIC**, and each NIC has a unique, permanent **MAC address**.
- An **Ethernet frame** has: **preamble**, **start frame delimiter**, **destination MAC**, **source MAC**, **length/type**, **data**, and **FCS**.
- The **length/type** field says how long the data is, or what type it is (like IPv4 or IPv6). The **FCS** is for **error checking**.
- Ethernet **doesn't care what's in the data**. It just delivers it NIC to NIC.
- **Encapsulation** = putting a message inside another format (letter in an envelope). **De-encapsulation** = taking it back out.
- A **frame** acts like an envelope with the destination and source addresses. If the format is wrong, the message isn't delivered.
- **IP** works like an envelope too, going source to destination over one or more networks.
